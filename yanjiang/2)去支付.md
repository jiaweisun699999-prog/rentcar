# 订单模块：去支付完整前后端生命周期流程

这是一次非常经典的**“前后端分离架构全生命周期”**剖析。我们将以“去支付”这个动作为例，顺着数据的流向，把项目里的相关代码完完整整地串联起来。

以下是这个完整闭环的 9 个详细步骤：

## 第一阶段：前端发起与“出境安检”

### 1. 前端点击触发 (`Orders.vue`)
当用户在“我的订单”页面点击“去支付”按钮时，触发了 `handlePayment` 方法：
```javascript
// Orders.vue (大约 250 行)
const handlePayment = async (order) => {
    // 组装业务参数
    await request.post('/pay/mock', {
      orderNo: order.orderId,
      payType: 1,
      amount: order.totalAmount
    });
    // ... 后续代码先挂起，等待请求返回
}
```
此时，前端准备发送一个 HTTP POST 请求，带着订单号等数据。但这个请求不会马上飞出去，而是被前端的一个“拦截器”拦下了。

### 2. 前端请求拦截器 (`src/utils/request.js`)
在 Axios 发送请求之前，必定会经过 `request` 拦截器：
```javascript
// request.js (第 11-20 行)
service.interceptors.request.use(
  config => {
    // 1. 去浏览器的本地存储里翻一翻，看看有没有用户登录时存下来的 token
    const token = localStorage.getItem('token');
    if (token) {
      // 2. 如果有，就强行塞进 HTTP 请求头(Headers)的 Authorization 字段里
      // 格式规范为 "Bearer " 加上 token 字符串
      config.headers['Authorization'] = 'Bearer ' + token;
    }
    return config; // 3. 携带好 token 后，放行请求
  }
);
```

### 3. 网络传输
带有 JSON 数据体和包含 Token 请求头的 HTTP 报文，通过互联网飞向 Spring Boot 后端服务器（比如 `http://localhost:8080/api/pay/mock`）。

## 第二阶段：后端鉴权与业务处理

### 4. 后端拦截器鉴权 (`JwtInterceptor.java`)
请求到达 Spring Boot 后，在进入 Controller 之前，被注册在系统里的 `JwtInterceptor` 拦截下来做“入境安检”：
```java
// JwtInterceptor.java (第 28-48 行)
public boolean preHandle(...) throws Exception {
    // 1. 从请求头里拿出刚才前端塞进去的 Token
    String token = request.getHeader("Authorization");
    
    // 2. 检查 Token 是否存在并且格式正确（以 "Bearer " 开头）
    if (StringUtils.hasText(token) && token.startsWith("Bearer ")) {
        token = token.substring(7); // 截掉 "Bearer " 前缀，保留纯粹的 token
        try {
            // 3. 用密钥解析 Token，如果没过期且合法，就能解析出内容
            Claims claims = jwtUtils.parseToken(token);
            Long userId = Long.valueOf(claims.getSubject()); // 提取出当初签发时存进去的用户ID
            
            // 4. 【非常关键】把用户ID存入当前线程上下文（ThreadLocal）。
            // 这样一来，后面的 Controller 和 Service 随时随地都能知道现在是谁在操作，不用满世界传参数。
            UserContext.setUserId(userId);
            
            return true; // 5. 校验通过，绿灯放行！请求进入 Controller。
        } catch (Exception e) {
             // 记录解析失败的日志...
        }
    }
    
    // 如果上面没 return true，说明 Token 是假的/没传/过期了
    response.setStatus(401); // 强行设置 HTTP 状态码为 401 (未授权)
    response.getWriter().write("{\"code\":401,\"msg\":\"未登录或Token已过期\"...}");
    return false; // 红灯拦截，请求到此为止，直接打回前端。
}
```

### 5. Controller 分发业务 (`OrderController.java`)
因为上一步返回了 `true`，请求终于来到了对应的 Controller 方法：
```java
// OrderController.java
@PostMapping("/pay/mock")
// @RequestBody 把前端传来的 JSON 自动转成了 Map 集合
public Result<String> payMock(@RequestBody Map<String, Object> params) {
    String orderNo = (String) params.get("orderNo");
    // 基本的参数校验...
    
    // 把活儿丢给 Service 层去干
    carOrderService.payOrder(orderNo);
    
    // Service 没抛异常，说明成功了，打包成统一格式返回
    return Result.success("支付成功", null);
}
```

### 6. Service 操作数据库 (`CarOrderServiceImpl.java`)
```java
// CarOrderServiceImpl.java
public void payOrder(String orderNo) {
    // 借助 MyBatis-Plus 拼装并执行 SQL: UPDATE car_order SET status = 1 WHERE order_no = ?
    LambdaUpdateWrapper<CarOrder> wrapper = new LambdaUpdateWrapper<>();
    wrapper.eq(CarOrder::getOrderNo, orderNo)
           .set(CarOrder::getStatus, 1);
    this.update(wrapper); 
}
```

### 7. 请求结束后的清理工作
当 Controller 返回了 `Result` JSON 字符串给前端后，后端拦截器的 `afterCompletion` 方法会被触发：
```java
// JwtInterceptor.java (第 51-54 行)
public void afterCompletion(...) {
    // 【必须做】清理 ThreadLocal 中的用户 ID。
    // 因为 Tomcat 线程池里的线程是会被复用的，如果不清理，下一个请求借用这个线程时可能会读取到前一个人的信息，导致严重的“串号”安全漏洞。
    UserContext.removeUserId(); 
}
```

## 第三阶段：前端接收与渲染

### 8. 前端响应拦截器解包 (`src/utils/request.js`)
后端返回的 JSON 数据抵达前端，在你的业务代码拿到之前，会先被 Axios 的响应拦截器处理：
```javascript
// request.js (第 28-51 行)
service.interceptors.response.use(
  response => {
    // response.data 就是后端 Controller 返回的那个 Result 对象：{code: 200, message: "支付成功", data: null}
    const res = response.data;
    
    // 1. 如果后端明确告诉我们业务成功了 (code === 200)
    if (res.code === 200) {
      // 脱掉 {code, message} 这层外衣，只把核心的 data 扔给具体的业务代码
      return res.data; 
    } else {
      // 2. 如果 code 不是 200，说明业务报错了（比如库存不足）
      ElMessage.error(res.msg); // 直接弹红色的报错框
      
      // 3. 特殊处理：如果发现后端报 401（也就是刚才后端拦截器拦截的情况）
      if (res.code === 401) {
        localStorage.removeItem('token'); // 说明 Token 已经废了，删掉它
        router.push('/login'); // 强制把用户踢回登录页
      }
      return Promise.reject(new Error(res.msg)); // 终止执行
    }
  }
);
```

### 9. 前端业务逻辑收尾 (`Orders.vue`)
因为上一步响应拦截器发现 `code === 200`，放行了结果，所以代码回到了我们最初的起点：
```javascript
// Orders.vue (大约 250 行)
const handlePayment = async (order) => {
  try {
    await request.post('/pay/mock', {...}); // 到这里，这个 await 终于等到了成功的执行结果！

    // 下面两行代码终于得以执行：
    // 1. 弹出绿色成功的 UI 提示
    ElMessage.success('尊享账单支付成功！门店正在为您调配准备车辆');
    
    // 2. 重新去调用后端的 /order/list 接口，拿取最新的包含已支付状态的列表，Vue 监测到数据变化，自动重绘页面。
    fetchOrders(); 
  } catch (error) {
    // 如果中间任何一环（网络断开、后端抛异常、拦截器报错）出了问题，都会跳到这里
    console.error(error);
  }
};
```

至此，一次点击所引发的全栈“长途旅行”圆满结束！这就是现代前后端分离项目（Vue3 + Spring Boot）最为标准和安全的交互模式。
