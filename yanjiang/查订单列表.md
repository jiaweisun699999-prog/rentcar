# 订单模块：查订单列表完整前后端生命周期流程

这也是一次经典的“前后端分离架构全生命周期”剖析。我们将以“打开我的订单页面（或刷新列表）”这个动作为例，顺着数据的流向，把项目里的相关代码串联起来。

以下是完整的 9 个详细步骤：

## 第一阶段：前端发起与“出境安检”

### 1. 前端页面挂载触发 (`Orders.vue`)
当用户在浏览器中打开“我的订单”页面时，Vue 3 的生命周期函数 `onMounted` 会自动执行，从而触发 `fetchOrders` 方法：
```javascript
// Orders.vue (大约 325 行)
onMounted(() => {
  fetchOrders();
});

// Orders.vue (大约 225 行)
const fetchOrders = async () => {
  if (!isLoggedIn.value) {
    router.push('/login'); // 判断用户是否登录，未登录直接拦截跳转
    return;
  }
  
  loading.value = true; // 开启页面 loading 动画
  try {
    // axios 发送携带分页参数的 GET 请求
    // 相当于访问 /api/order/list?page=1&pageSize=20
    const res = await request.get('/order/list', { params: { page: 1, pageSize: 20 } });
    // ... 后续代码先挂起，等待请求返回
  }
}
```

### 2. 前端请求拦截器 (`src/utils/request.js`)
在 Axios 真正把请求发往网络前，必定会经过 `request` 拦截器：
```javascript
// request.js 
service.interceptors.request.use(
  config => {
    // 1. 去浏览器的本地存储里取出 token
    const token = localStorage.getItem('token');
    if (token) {
      // 2. 强行塞进 HTTP 请求头(Headers)的 Authorization 字段里
      config.headers['Authorization'] = 'Bearer ' + token;
    }
    return config; // 3. 携带好 token 后，放行请求
  }
);
```

### 3. 网络传输
带有查询参数（`?page=1&pageSize=20`）和包含 Token 请求头的 HTTP GET 报文，通过互联网飞向 Spring Boot 后端服务器。

## 第二阶段：后端鉴权与业务处理

### 4. 后端拦截器鉴权 (`JwtInterceptor.java`)
与支付接口一样，请求到达 Spring Boot 后，被 `JwtInterceptor` 拦截下来做“入境安检”：
```java
// JwtInterceptor.java
public boolean preHandle(...) throws Exception {
    String token = request.getHeader("Authorization");
    
    if (StringUtils.hasText(token) && token.startsWith("Bearer ")) {
        token = token.substring(7); 
        try {
            // 解析 Token，提取出用户ID
            Claims claims = jwtUtils.parseToken(token);
            Long userId = Long.valueOf(claims.getSubject()); 
            
            // 【关键】把用户ID存入当前线程上下文（ThreadLocal）。
            // 后面的查表逻辑就能知道查哪个用户的订单了！
            UserContext.setUserId(userId);
            return true; // 校验通过，绿灯放行
        } catch (Exception e) {}
    }
    // Token无效则返回 401 报错
    response.setStatus(401);
    return false; 
}
```

### 5. Controller 分发业务 (`OrderController.java`)
请求通过拦截器，来到了对应的 GET 接口方法：
```java
// OrderController.java (大约 33 行)
@GetMapping("/order/list")
public Result<Page<OrderListVo>> list(OrderQueryDto dto) {
    // Spring Boot 自动把 URL 中的 page=1&pageSize=20 组装成了 dto 对象
    
    // 调用 Service 层去查数据库，返回带有分页信息的数据
    Page<OrderListVo> page = carOrderService.getOrderPage(dto);
    
    // 使用 Result.success 将数据包裹并返回给前端
    return Result.success(page);
}
```

### 6. Service 操作数据库并转换格式 (`CarOrderServiceImpl.java`)
这是最重的一步，不仅要查，还要格式化：
```java
// CarOrderServiceImpl.java 
public Page<OrderListVo> getOrderPage(OrderQueryDto dto) {
    // 1. 组装查询条件，比如只查当前用户的订单：WHERE user_id = ?
    LambdaQueryWrapper<CarOrder> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(CarOrder::getUserId, UserContext.getUserId()); 
    wrapper.orderByDesc(CarOrder::getCreateTime); // ORDER BY create_time DESC
    
    // 2. 执行分页查询 (MyBatis-Plus 自动拦截生成 LIMIT/OFFSET 语句)
    Page<CarOrder> page = new Page<>(dto.getPage(), dto.getPageSize());
    this.page(page, wrapper);
    
    // 3. 将原生的 CarOrder (数据库实体) 转换成前端需要的 OrderListVo
    List<OrderListVo> voList = page.getRecords().stream().map(order -> {
        OrderListVo vo = new OrderListVo();
        vo.setOrderId(order.getOrderNo());
        // ... 日期格式化处理，塞入其它所需数据
        return vo;
    }).collect(Collectors.toList());
    
    // 4. 打包进新的分页对象中返回给 Controller
    Page<OrderListVo> voPage = new Page<>(page.getCurrent(), page.getSize(), page.getTotal());
    voPage.setRecords(voList);
    return voPage;
}
```

### 7. 请求结束后的清理工作
当 Controller 返回了 `Result` 之后，拦截器清理现场：
```java
// JwtInterceptor.java 
public void afterCompletion(...) {
    // 清理 ThreadLocal 中的用户 ID，防止串号漏洞
    UserContext.removeUserId(); 
}
```

## 第三阶段：前端接收与渲染

### 8. 前端响应拦截器解包 (`src/utils/request.js`)
后端返回的 JSON 数据抵达前端，Axios 响应拦截器先接手：
```javascript
// request.js 
service.interceptors.response.use(
  response => {
    const res = response.data; // {code: 200, message: "success", data: {records: [...], total: ...}}
    
    if (res.code === 200) {
      // 脱掉 {code, message} 这层外衣，只把核心的分页 data 扔给具体的业务代码
      return res.data; 
    } else {
      // 错误处理、拦截 401 踢回登录等...
      return Promise.reject(new Error(res.msg)); 
    }
  }
);
```

### 9. 前端业务逻辑收尾与重新渲染 (`Orders.vue`)
最后，流程回到了 `Orders.vue`：
```javascript
// Orders.vue 
const fetchOrders = async () => {
  // ...
  try {
    // await 终于等到了解包出来的 data (即 res)
    const res = await request.get('/order/list', { params: { page: 1, pageSize: 20 } });
    
    // 把查到的具体列表数据 (res.records) 赋值给页面的响应式变量 orderList
    orderList.value = res.records || [];
    
    // Vue 的响应式系统侦测到 orderList.value 发生了改变，
    // 立马通知页面的 <el-table> 进行重新渲染，用户的屏幕上就刷出了最新的订单列表！
  } catch (error) {
    // ...
  } finally {
    loading.value = false; // 关闭 loading 动画
  }
};
```

至此，通过这 9 步，“查订单列表”的指令成功完成了从前端发起到后端查表再到前端页面展示的完美闭环！
