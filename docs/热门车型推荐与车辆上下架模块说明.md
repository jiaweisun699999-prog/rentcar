# 热门车型推荐与车辆上下架模块说明

## 1. 模块概述

本项目是前后端分离的租车系统，车辆相关功能主要围绕“车型”和“实体车辆”展开。

- **车型 / SPU**：表示一种车型，例如“特斯拉 Model 3”“比亚迪 汉”。对应数据库表 `car_model`。
- **实体车辆 / SKU**：表示门店里一辆真实可出租车辆，例如某辆车的车牌号、所属门店、日租金。对应数据库表 `car_instance`。
- **门店**：车辆归属和取还车地点。对应数据库表 `store_info`。
- **订单**：用于判断某辆车在某个时间段是否已被占用。对应数据库表 `car_order`。

首页“热门车型推荐”模块的核心作用是：

1. 在首页展示推荐车型卡片。
2. 支持按城市筛选推荐车型。
3. 展示车型名称、图片、类型、座位/车门、日租金、所在地等信息。
4. 点击车型后展示详情弹窗。
5. 用户选择取还车时间后，可跳转到选车预订页。

后台“车辆增加下架模块”的核心作用是：

1. 管理员上架新的车型。
2. 上传车型展示图。
3. 管理员下架已有车型。
4. 当前代码中也保留了向门店投放实体车辆的功能。

## 3. 数据表设计关系

### 3.1 `car_model` 车型表

对应实体：`CarModel.java`

主要字段：

| 字段 | 含义 |
|---|---|
| `id` | 车型 ID |
| `brand_series` | 品牌车系，例如“比亚迪 汉” |
| `car_type` | 车型类型，例如“经济型”“SUV”“豪华型” |
| `seats_doors` | 座位车门信息，例如“5座4门” |
| `main_image` | 车型主图 URL |
| `create_time` | 创建时间 |
| `update_time` | 更新时间 |
| `is_deleted` | 逻辑删除字段 |

`CarModel` 中使用了 MyBatis-Plus 的逻辑删除：

```java
@TableLogic
private Integer isDeleted;
```

所以后台执行车型下架时，本质上是逻辑删除，而不是物理删除数据库记录。

---

### 3.2 `car_instance` 实体车辆表

对应实体：`CarInstance.java`

主要字段：

| 字段 | 含义 |
|---|---|
| `id` | 实体车辆 ID |
| `model_id` | 所属车型 ID，关联 `car_model.id` |
| `store_id` | 所属门店 ID，关联 `store_info.id` |
| `plate_number` | 车牌号 |
| `daily_rent_price` | 日租金 |
| `status` | 车辆状态 |
| `create_time` | 创建时间 |
| `update_time` | 更新时间 |
| `is_deleted` | 逻辑删除字段 |

实体车辆的作用是给车型补充真实业务数据：

- 日租金来自 `car_instance.daily_rent_price`
- 车牌号来自 `car_instance.plate_number`
- 所在城市通过 `car_instance.store_id` 查询 `store_info.city_name`
- 预订跳转用的门店 ID 来自 `car_instance.store_id`

---

### 3.3 `store_info` 门店表

热门车型按地区推荐时，需要通过门店表判断车辆所在地。

核心关系：

```text
car_instance.store_id -> store_info.id -> store_info.city_name
```

例如：

```text
car_instance.store_id = 101
store_info.id = 101
store_info.city_name = 上海市
```

则该实体车辆所在地为“上海市”。

---

### 3.4 `car_order` 订单表

在选车页按门店和时间查询可租车型时，需要用订单表排除已经被占用的车辆。

时间冲突判断逻辑：

```text
已有订单开始时间 < 用户选择的还车时间
并且
已有订单结束时间 > 用户选择的起租时间
```

代码中对应条件：

```java
.lt(CarOrder::getStartTime, endTime)
.gt(CarOrder::getEndTime, startTime)
```

如果满足这个条件，说明两段租车时间发生重叠，该车不能被再次预订。

## 4.4 为什么首页使用 `/car/model/list` 而不是 `/car/recommend`

后端虽然存在接口：

```http
GET /api/car/recommend
```

但是当前首页代码实际使用的是：

```http
GET /api/car/model/list
```

原因是 `/car/model/list` 支持：

1. 分页。
2. 城市筛选。
3. 返回 `storeId`。
4. 返回 `locationCity`。
5. 能和后续选车预订页的查询参数衔接。

而 `/car/recommend` 当前实现是固定取最新 8 个车型，不支持分页和城市筛选。

## 4.5 城市筛选如何实现

首页先加载门店列表：

```js
const loadStores = async () => {
  const res = await request.get('/store/list', { params: { page: 1, pageSize: 100 } });
  stores.value = res.records || [];
};
```

再从门店列表中提取城市：

```js
const cities = computed(() => {
  const list = stores.value.map(s => s.cityName).filter(Boolean);
  return [...new Set(list)];
});
```

城市按钮通过 `el-radio-group` 展示：

```vue
<el-radio-group v-model="selectedCity" @change="handleCityChange">
  <el-radio-button label="">全国</el-radio-button>
  <el-radio-button v-for="city in cities" :key="city" :label="city">
    {{ city }}
  </el-radio-button>
</el-radio-group>
```

切换城市后：

```js
const handleCityChange = () => {
  pagination.value.page = 1;
  loadRecommendCars();
};
```

流程：

```text
点击城市按钮
  -> selectedCity 改变
  -> 页码重置为 1
  -> 重新请求 /car/model/list
  -> 后端根据 cityName 筛选车辆
  -> 首页重新渲染
```

## 4.7 后端查询逻辑

核心方法：

```text
CarServiceImpl.getModelList(CarModelQueryDto queryDto)
```

它分三种情况处理。

### 4.7.1 带门店和时间：查询可租车型

如果请求中有：

```text
storeId + startTime + endTime
```

代码会进入：

```java
if (hasAvailableQuery(queryDto)) {
    return getAvailableModelPage(queryDto, pageNum, pageSize);
}
```

这个场景主要用于选车页，不是首页普通展示。

逻辑：

1. 查询该门店下的车辆实例。
2. 排除准备中、维修中的车辆。
3. 根据订单时间排除冲突车辆。
4. 按车型分组。
5. 返回可租车型分页结果。

---

### 4.7.2 不传城市：全国热门车型

如果没有传 `cityName`：

```java
LambdaQueryWrapper<CarModel> queryWrapper = new LambdaQueryWrapper<>();
queryWrapper.orderByDesc(CarModel::getCreateTime);
Page<CarModel> modelPage = this.page(new Page<>(pageNum, pageSize), queryWrapper);
```

含义：

- 直接从 `car_model` 查车型。
- 按创建时间倒序。
- 分页返回。

所以当前“热门”并不是按照点击量或订单量排序，而是：

```text
最新上架的车型优先展示
```

---

### 4.7.3 传入城市：按地区推荐

如果传入了 `cityName`，例如“上海市”，后端会：

第一步，查询该城市下的所有门店：

```java
List<StoreInfo> stores = storeInfoMapper.selectList(
    new LambdaQueryWrapper<StoreInfo>().eq(StoreInfo::getCityName, queryDto.getCityName())
);
```

第二步，提取这些门店 ID：

```java
List<Long> storeIds = stores.stream().map(StoreInfo::getId).toList();
```

第三步，查询这些门店下未出租车辆：

```java
instanceWrapper.ne(CarInstance::getStatus, 2);
instanceWrapper.in(CarInstance::getStoreId, storeIds);
```

第四步，提取车型 ID：

```java
Set<Long> unrentedModelIds = unrentedInstances.stream()
    .map(CarInstance::getModelId)
    .collect(Collectors.toSet());
```

第五步，根据车型 ID 查询车型：

```java
queryWrapper.in(CarModel::getId, unrentedModelIds);
queryWrapper.orderByDesc(CarModel::getCreateTime);
```

所以城市推荐逻辑可以总结为：

```text
城市 -> 门店 -> 未出租实体车辆 -> 车型 ID -> 车型信息
```

## 4.8 日租金、车牌、城市、门店 ID 如何组装

后端从 `car_model` 查出的只是车型基础信息，还需要从 `car_instance` 和 `store_info` 补充展示字段。

### 4.8.1 日租金 `dailyPrice`

调用：

```java
Map<Long, BigDecimal> dailyPriceMap = getMinDailyPriceMap(modelIds);
```

实现逻辑：

1. 查询这些车型对应的所有实体车辆。
2. 按 `modelId` 分组。
3. 取每个车型下最低的 `dailyRentPrice`。

含义：

```text
一个车型可能有多辆实体车，不同门店价格可能不同，首页展示最低日租金。
```

---

### 4.8.2 车牌号 `licensePlate`

调用：

```java
Map<Long, String> licensePlateMap = getLicensePlateMap(modelIds, selectedCity);
```

实现逻辑：

1. 根据车型 ID 查询 `car_instance`。
2. 如果传入城市，则优先选择该城市门店下的车辆。
3. 返回该车型对应的一个车牌号。

如果没有真实车牌，代码中存在兜底逻辑：

```java
licensePlate = generatePlateForModel(model.getId());
```

---

### 4.8.3 车辆所在地 `locationCity`

调用：

```java
Map<Long, String> cityNamesMap = getCityNameMap(modelIds, selectedCity);
```

实现逻辑：

1. 查询车型对应的车辆实例。
2. 获取实例中的 `storeId`。
3. 查询门店表 `store_info`。
4. 取 `store_info.city_name`。
5. 如果传入城市，则优先返回目标城市的实例所在地。

---

### 4.8.4 门店 ID `storeId`

调用：

```java
Map<Long, Long> storeIdsMap = getStoreIdMap(modelIds, selectedCity);
```

`storeId` 主要用于首页点击预订后跳转选车页。

如果传入城市，后端会优先返回该城市门店下的车辆实例 `storeId`。

## 4.11 点击立即预订后的跳转

详情弹窗点击预订按钮会执行：

```js
bookFromHomeDetail(car)
```

核心逻辑：

```js
let targetStoreId = car.storeId;

if (!targetStoreId) {
  targetStoreId = searchParams.value.storeId;
  if (car.locationCity) {
    const storeInCarCity = stores.value.find(s => s.cityName === car.locationCity);
    if (storeInCarCity) {
      targetStoreId = storeInCarCity.id;
    }
  }
}
```

门店选择优先级：

1. 优先使用后端返回的 `car.storeId`。
2. 如果没有，则使用首页选择的取车门店。
3. 如果车型有 `locationCity`，则尝试匹配该城市的门店作为兜底。

跳转参数：

```js
router.push({
  path: '/search',
  query: {
    storeId: targetStoreId,
    startTime: searchParams.value.timeRange[0],
    endTime: searchParams.value.timeRange[1],
    autoBookModelId: car.id
  }
});
```

最终跳转到：

```text
/search?storeId=101&startTime=...&endTime=...&autoBookModelId=23
```

```java
@Override
public void addInstance(CarInstanceReqDto reqDto) {
    if (reqDto == null) {
        throw new RuntimeException("车辆参数不能为空");
    }
    if (reqDto.getModelId() == null) {
        throw new RuntimeException("车型ID不能为空");
    }
    if (carModelMapper.selectById(reqDto.getModelId()) == null) {
        throw new RuntimeException("车型不存在");
    }
    if (reqDto.getStoreId() == null) {
        throw new RuntimeException("门店ID不能为空");
    }
    if (!StringUtils.hasText(reqDto.getPlateNumber())) {
        throw new RuntimeException("车牌号不能为空");
    }
    if (reqDto.getDailyRentPrice() == null || reqDto.getDailyRentPrice().compareTo(BigDecimal.ZERO) <= 0) {
        throw new RuntimeException("日租金必须大于0");
    }

    CarInstance carInstance = new CarInstance();
    carInstance.setModelId(reqDto.getModelId());
    carInstance.setStoreId(reqDto.getStoreId());
    carInstance.setPlateNumber(reqDto.getPlateNumber());
    carInstance.setDailyRentPrice(reqDto.getDailyRentPrice());
    carInstance.setStatus(0);
    this.save(carInstance);
}
```

2. 首页可以展示真实车牌号。
3. 城市推荐可以根据门店城市找到该车型。

# 11. 关键业务规则

## 11.1 车型和车辆实例必须配合使用

只新增车型 `car_model`，可以让首页显示车型基础信息。

但要完整支持预订，最好同时新增实体车辆 `car_instance`。

原因：

- `dailyPrice` 需要从实体车辆取。
- `licensePlate` 需要从实体车辆取。
- `locationCity` 需要通过实体车辆的门店取。
- `storeId` 需要从实体车辆取。
- 实际可租判断需要基于实体车辆和订单。

---

## 11.2 当前热门排序规则

当前热门车型不是按订单量排序，而是：

```text
按 car_model.create_time 倒序
```

也就是：

```text
越新上架的车型越靠前
```

如果将来要做真正的“热门”，可以改为按订单数量、浏览次数或收藏数量排序。

---

## 11.3 城市推荐依赖门店和实体车辆

按城市筛选时，后端不会只看车型表，而是通过：

```text
城市 -> 门店 -> 实体车辆 -> 车型
```

因此，如果某个车型没有投放到上海门店，那么选择“上海市”时，该车型不会作为上海推荐车型出现。

---

## 11.4 已出租车辆不参与城市推荐

当前城市推荐中有条件：

```java
instanceWrapper.ne(CarInstance::getStatus, 2);
```

含义：

```text
排除 status = 2 的已出租车辆
```

如果一个车型在某城市下所有实体车辆都已出租，那么该车型不会出现在该城市推荐中。

---

## 11.5 选车页可租判断更严格

首页热门推荐主要是展示。

真正进入选车页时，会根据：

1. 门店 ID。
2. 起租时间。
3. 还车时间。
4. 车辆状态。
5. 订单冲突。

重新判断某辆车是否可租。

因此首页看到某个车型，并不代表任意时间都能租。最终是否可租，以选车页按时间查询结果为准。

# 12. 常见问题说明

## 12.1 为什么热门车型为空

可能原因：

1. 后端没有启动。
2. 数据库连接失败。
3. `application.yml` 中 MySQL 密码错误。
4. 前端请求接口失败。
5. 城市筛选后，该城市没有未出租车辆。
6. `car_model` 数据为空或被逻辑删除。

排查顺序：

```text
后端控制台是否启动成功
  -> 浏览器 Network 中 /api/car/model/list 是否 200
  -> 后端日志是否有数据库连接错误
  -> 数据库 car_model 是否有数据
  -> 数据库 car_instance 是否有对应门店车辆
```

---

## 12.2 为什么车型有图片但别人拉取项目后看不到

如果 `car_model.main_image` 存的是本地上传后的 URL，例如：

```text
http://localhost:8080/uploads/2026-05-25/xxx.png
```

那么其他人拉取代码后，如果没有对应的 `uploads` 文件，就无法访问图片。

解决方式：

1. 将图片放入项目资源目录并配置静态访问。
2. 或将 `uploads` 目录中的图片一起同步给其他开发者。
3. 或重新通过 `/api/upload` 上传并更新 `main_image`。

---

## 12.3 为什么点击热门车型跳转后找不到该车

常见原因：

1. 该车型没有对应实体车辆。
2. 实体车辆不在跳转的门店。
3. 该时间段车辆已有订单冲突。
4. 车辆状态为准备中或维修中。
5. 后端返回的 `storeId` 与车辆实际门店不一致。

核心原则：

```text
首页展示依赖车型数据，实际可租依赖实体车辆 + 门店 + 时间 + 订单。
```

# 14. 总结

热门车型推荐模块的核心是：

```text

实体车辆表 car_instance 负责提供真实租金、车牌和门店，
门店表 store_info 负责提供城市信息，
订单表 car_order 负责判断指定时间段是否可租。
```

车型上架模块的核心是：

```text
管理员填写车型基础信息和图片，
```

```text
管理员点击下架，

后端通过 MyBatis-Plus 逻辑删除 car_model，
之后前台和后台默认查询都不再显示该车型。
```

实体车辆投放模块的核心是：

```text
管理员为某个车型选择具体门店，填写车牌和日租金，
后端保存到 car_instance，
该车型才拥有真实可租车辆，才能更准确地参与城市推荐和预订流程。
```
